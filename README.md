# Managing AI-Empowered Teams: the FBB case repository

This repository holds everything you work with in Session 1 and 2. You open it in the GitHub Copilot app.

The client is **Fake Bright Bank (FBB)**, a fictional mid-sized EU bank. Its board wants to know whether its risk data aggregation and liquidity reporting meet supervisory expectations, and what has to change. The regulation is real, the bank is not. The files and statements contain false claims on purpose.

## What's where

| Folder            | Contents                                                                                                                                  |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `case/`           | The client material: case brief, sources guide, FBB's data governance policy, the LCR disclosure, and the draft board deck from Session 1 |
| `sources/`        | PDF copies of BCBS 239, the ECB guide and the LCR rules (see `case/02-sources.md`)                                                        |
| `templates/`      | Problem-setting brief, the four review questions, the CO-STAR prompt pattern, the gap-analysis table, and an empty agent definition       |
| `worksheets/`     | Step-by-step instructions for Hands-on 1 and Hands-on 2                                                                                   |
| `.github/agents/` | The Reference & Number Checker agent. Agents in this folder appear in Copilot's agent picker                                              |
| `docs/`           | How to add an MCP server                                                                                                                  |
| `reviews/`        | Where agents save their check reports                                                                                                     |

## Ground rules for today

- Work only with the material in this repository and the official sources. Don't paste in real client data.
- Every claim needs a source you can open. If the AI can't point to one, the claim doesn't count.
- Keep what you produce. You'll compare results with others, and you can take the repository home as a template for your own team.

## Getting started

1. Open this repository in the GitHub Copilot app and start a new session.
2. Check that you can see the files in `case/` and `sources/`.
3. Open `worksheets/hands-on-1-regulation-to-requirements.md` and follow the steps.
